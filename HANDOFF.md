## Done this session (bug fix — "no response coming back" while a chat is in flight)
- **Diagnosis** — the running uvicorn process had a frozen event loop: TCP accepted, but even `GET /` returned nothing. Root cause: `async def chat()` called the blocking `rag_chain.invoke()` directly on the loop thread (sync LLM HTTP to the slow, 429-prone free-tier model; no explicit timeout — openai client defaults are 600 s/attempt x 3 tries). While one chat waited on the provider, every other request (`/`, `/api/status`, `/api/context`) queued behind it with no response; the UI just showed a loading dot forever. Stuck process was 0.1% CPU, all threads sleeping in network reads.
- **Fix** — `/api/chat` and both ingest endpoints now run their blocking work via `loop.run_in_executor` (the same pattern `/api/context` already used); provider errors surface as 502 with detail (the UI renders `data.detail`). `ChatOpenAI` now has `timeout=300, max_retries=1` so a hung provider fails in ~10 min, not ~30.
- **`python app.py` now runs the server** (`__main__` guard; port 5001, `PORT` env override) — resolves old outstanding #6; `CLAUDE.md` commands section aligned to port 5001, convention updated ("never call blocking chain/ingest code directly in an async def endpoint").
- **Verified live** — py_compile clean (py3.9); fresh boot (PID in server log at `/tmp/cp_rag_server.log`): `/api/status` 200 in ~30 ms; WITH a chat in flight, `/api/status` (~30 ms) and `/` (200, ~20 ms) still answered; one free-model chat (0 credits) returned a correct three-section answer (protocol / MOH guidance labelled "not protocol content" / local context) with 2 sources; context warmup build cached within the TTL (`"cached (Ns old)"`).
- **Markup fix** — user reported raw `**bold**`/`*italic*` showing in chat answers: the model emits markdown by default, but the UI renders escaped plain text (by design — no framework/build step). Fix: (1) `PROMPT_TEMPLATE` now has a plain-text formatting rule ("NO markdown support — never use **bold**, *italic*, # headings, or backticks; dash bullets + blank lines fine"); (2) `.msg` CSS gained `white-space: pre-wrap` so the model's line breaks render (previously collapsed into one paragraph). Verified with one free-model chat: 0 asterisks/backticks/hash-headings in the answer, 15 line breaks, structured sections intact. Alternative if markdown rendering is ever wanted: a CDN renderer (marked.js) — parked, needs explicit go-ahead (new external dependency).

Two UI fixes in `static/index.html`: (1) the loading bubble now shows a live elapsed counter with an explicit "free-tier model, can take a few minutes" hint (cleared in `finally`); (2) `checkStatus` now re-polls every 10 s while not ready, so a page loaded during a server restart self-heals instead of leaving the send button permanently disabled.
